# 04. 데이터베이스

- 작성일 2026-11-26 · 기준: `Backend/app/database/models.py`(모델 클래스 44개), `seed.py`, `db_url.py`.
- DB: MariaDB 10.11(컨테이너 `control-db`, 호스트 포트 3307→3306). ORM: SQLAlchemy + PyMySQL. 스키마명은 `APP_ENV` 와 짝(prod=`control_system`, dev=`control_system_dev`; `.env.example`).

## 1. 스키마 관리 방식

- 스키마 변경은 별도 마이그레이션 도구 없이 `seed.py` 의 `migrate_*` 함수로 처리합니다. 칸 삭제·이름 변경과 이력 관리가 필요해지면 Alembic 같은 도구를 검토할 수 있습니다.
- 기동할 때 `Base.metadata.create_all()` 로 **없는 테이블만** 만들고(`main.py:160`), 이어서 `seed_all(db)` 안의 `migrate_*` 함수가 **없는 칸을 ALTER TABLE 로 추가**합니다(멱등). 예: `migrate_menu_info_columns`, `migrate_schedule_info_columns`, `migrate_service_session_*`, `migrate_voice_scenario_columns`, `migrate_drop_location_via_column`.
- **칸을 추가하려면** ① `models.py` 에 칸 정의 ② `seed.py` 에 멱등 `migrate_*` 추가 후 `seed_all` 에 등록. 모델에만 쓰면 기존 DB 에는 칸이 생기지 않아 조회가 실패합니다(스케줄러를 seed 이후에 켜는 이유 — `main.py:210`).
- 칸 삭제·이름 변경은 자동으로 되지 않습니다(`DROP` 은 `migrate_drop_location_via_column` 처럼 별도 함수).
- 초기 데이터: 빈 DB 첫 기동 시 기본 계정 3개(superadmin / manager / user)를 `SEED_*_PASSWORD` 환경 변수로 만들고, 메뉴·권한·내장 카메라·음성 시나리오 기본값(`seed_voice_scenarios`)을 시드합니다.
- 신규 PC 배포: `db/init/01_control_system_dev.sql.gz`(약 232MB, 10-06 덤프)를 윈도우 compose 가 빈 볼륨일 때 자동 import. 최신 덤프로 갱신할지는 결정 사항.
- 외부 DB: `.env` 의 `DATABASE_URL` 에 넣으면 내장 db 없이 붙습니다(재빌드 불필요).

## 3. 데이터 함정 (반드시 읽기)

1. **장소 칸 이름은 `LacationName`(오타)이 정본**입니다. `LocationName` 으로 쓰면 안 됩니다.
2. **장소를 이름으로 연결하는 곳이 많습니다**(경로·경유 정보·구간 `route_info` 의 시작/끝, 층 이동 도착 위치). **운영 중인 장소 이름 변경·재생성 금지**. 이름에 "엘리베이터/EV"가 들어가면 층 이동 로직이 반응하니 주의.
3. **지도를 다시 만들면 지도 번호가 새로 생깁니다.** 패치·시나리오·환경 변수(`ROUTE_GRAPH_MAPS`, `AUTO_DETOUR_DISABLED_MAPS`)의 맵 번호를 확인하세요. 현재 운영 맵 번호 예: 1F=47, 3F=49(기록), 2F 주차장=46.
4. **순환 참조 주의:** `cluster.deps` ↔ `robot_control.charge`(DB 가 아니라 코드).
5. **MariaDB 격리 수준:** 같은 거래 안 재조회는 처음 값이 나옵니다. 동시 실행 방지는 프로세스 안 잠금(백엔드 작업자 1개 전제).
6. **운영 DB 는 조회만** 합니다. 검증은 `sim/`(임시 SQLite)·격리 DB 에서. `docker compose down -v` 금지(DB 볼륨 삭제).
7. **충전소 재등록 ≠ 맵 초기 위치.** `map_init_pose` 는 따로 갱신해야 합니다.
8. 위험구역(`danger`) 기능은 10-16 에 코드를 삭제했고 `location_info.Polygon` 칸은 비어 있는 채로 남아 있었습니다(코드에서 `Polygon` 칸은 제거됨 — 컬럼은 DB 에 남을 수 있음).
9. **장소 타입(`Category`)은 4종** waypoint·work·standby·charge. 충전소는 화면에서 [충전소 생성] 버튼으로만 만들 수 있고 기존 충전소는 타입 고정.
10. 시나리오 단계 문구·retryCount 실제 값은 **DB 에 있어** 코드만 보면 알 수 없습니다. 수정은 화면(음성 관리) 또는 DB 패치로 하며, 패치는 `--revert` 가능하게 만들었습니다.

## 4. 백업·복구

- 화면 설정 › DB 백업(`/api/backup/download`, 관리자)이 mysqldump 를 내려줍니다.
- 배포 전에는 이미지 이름표(`bak_날짜`)와 DB 덤프(`_backup/db_날짜…`)를 남기는 관행이 있습니다.
- 맵 파일은 DB BLOB 이 원본 역할이라, 로컬 `static/maps` 가 없어도 기동 시 복원됩니다(`map_file_store.sync_all_from_db`).
