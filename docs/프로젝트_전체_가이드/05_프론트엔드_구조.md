# 05. 프론트엔드 구조 (`Frontend/`)

- 작성일 2026-11-26 · 기준: 작업 폴더 코드. 폴더·파일 목록은 2026-11-26 `ls` 로 확인, 화면별 설명 일부는 2026-10-15 기록에 기댔습니다.
- 도커 컨테이너 `control-frontend`, 포트 3001(nginx).

## 1. 기술 스택과 빌드 방식

| 항목 | 값 | 근거 |
|---|---|---|
| 프레임워크 | Next.js 15.5.x, React 18.3, TypeScript 5.9 | `package.json` |
| 스타일 | Tailwind 4(`@tailwindcss/postcss`) + 페이지별 CSS Modules(`*.module.css`) | `package.json`, 폴더 구조 |
| 3D 맵 | Three.js | `components/map3d/` |
| 엑셀 내보내기 | xlsx | 통계 탭 |
| 테스트 | Vitest + Testing Library(jsdom), `app/**/*.test.ts(x)` 약 46개 | `vitest.config.ts` |
| 빌드 | `next build` → **정적 export**(`output: 'export'`, `trailingSlash: true`) → `out/` | `next.config.js` |
| 서빙 | nginx(3001). 해시된 `_next/static` 은 영구 캐시, HTML 은 `no-cache` + SPA 폴백 | `nginx.conf` |
| 이미지 | node:20-alpine 으로 빌드 후 nginx:alpine 에 `out/` 복사 | `Dockerfile` |

- 화면은 정적 파일이고, 모든 데이터는 브라우저가 백엔드(8010)를 직접 호출합니다.
- **API 주소:** `app/config.ts` 의 `getApiBase()` 가 `http://<접속 hostname>:8010` 을 돌려줍니다(localhost 든 원격이든 같은 방식). 백엔드 포트 8010 은 다른 프로젝트가 8000 을 점유해 분리한 값입니다.
- **영상 주소:** `getWebrtcBase()` — 기본은 접속 hostname:8889, `NEXT_PUBLIC_MEDIAMTX_HOST` 가 있으면 그 호스트. **이 값은 빌드할 때 코드에 구워지므로 바꾸면 프론트 재빌드가 필요**합니다.
- 개발 서버(`npm run dev`, 3000)에서는 `next.config.js` 의 `rewrites()` 가 `/api /DB /robot /nav /map /Video /static /user /ws` 를 `localhost:8010` 으로 넘깁니다(같은 출처가 되어 쿠키 문제가 없음). **빌드된 정적 사이트에서는 이 프록시가 동작하지 않습니다.**
- 빌드 중 린트는 꺼져 있습니다(`eslint.ignoreDuringBuilds`, 기존 오류 112건). 검사는 `npm run lint`/`npx eslint <파일>` 로 따로 돌리며 **바꾼 파일에 새 오류를 늘리지 않는** 것이 규칙입니다. `eslint.config.mjs` 를 Next 16 양식으로 되돌리지 마세요(설치본은 15).

## 2. 폴더 구조 (`Frontend/app/`)

```
app/
  layout.tsx / page.tsx / globals.css   최상위 레이아웃·진입(리다이렉트)·전역 CSS
  config.ts · types.ts                  API·WebRTC 주소, 공통 타입
  (auth)/login/                         로그인(사이드바 없음)
  (pages)/                              로그인 후 화면(공통 레이아웃: 인증 확인·헤더·사이드바·전역 알림 감시)
    dashboard/                          실시간 대시보드
    scheduleManagement/                 작업 일정
    operationManagement/                운영 관리(로봇·사업장)
    mapManagement/                      맵 관리
    dataManagement/                     데이터 관리(로그·통계·영상·음성)
    alerts/                             알림·공지
    settings/                           설정(권한·비밀번호·DB 백업)
  components/                           공용 컴포넌트
  context/                              전역 상태(Provider)
  hooks/ lib/ utils/ constants/         훅·API 클라이언트·도메인 판정·유틸·상수
```

메뉴와 라우트의 연결은 `constants/menuRouteMap.ts`, 메뉴 권한은 백엔드 `menu_info`(키: dashboard, schedule-list, robot-list, business-list, map-edit, place-list, path-list, video, statistics, log, voice, alert-*, menu-permissions, password-change, db-backup)와 `PermissionGuard` 가 맞춥니다.

## 3. 화면별 역할

| 화면 | 주요 내용 |
|---|---|
| 대시보드 | 로봇 카드·통계, 지도(로봇 마커·장소·경로), 카메라 슬롯(WebRTC), 공지, 작업 일정 타임라인. 엘리베이터·자동문·경유지 도착 진행 오버레이, 층 변경·작업 복귀 모달 |
| 작업 일정 | 주·월 달력, 일정 등록·상세·반복(`ScheduleInsert/Detail/RepeatConfirm`; 상시 대기 응대 방식 단발·단순 동작·안내 시나리오 선택 규칙은 `modals/standbyForm.ts`), 상시 대기 집계(`StandbyTab`), 회차 실행 이력(`RunHistory`) |
| 운영 관리 | 로봇 목록·상세(실시간 상태·현재 작업·모듈 관리), 상시 대기 응대 현황(`StandbyLiveChips`; 단순 동작 근무는 "단순 동작" 꼬리표만 보이고 관제 개입 버튼 없음), 사업장·층 관리 |
| 맵 관리 | 맵 편집(맵핑 시작·진행·완료, 로봇 맵 가져오기·동기화), 장소(POI) 관리, 경로·구간·경유지 옵션, 시설(자동문), 엘리베이터 정차 설정, 노드망 편집 |
| 데이터 관리 | 로그 탭, 통계 탭(KPI·차트·엑셀), 영상 탭(녹화 재생), **음성 탭**(목적지 사전·확인어·설정·도착 멘트·시나리오 목록/상세·안내 세션 카드·반복·일시정지·구간 테스트·보행 유지 토글·시나리오 편집기) |
| 알림 | 알림 목록·검색·읽음, 공지 등록·수정·삭제 |
| 설정 | 사용자 권한·등록, DB 백업 다운로드, (메뉴 관리는 임시 비노출) |

원격 제어 모달(`components/modal/remote/`)에 방향 패드·모드·자세·로봇팔·카메라·녹화·제어권·재조정이 모여 있습니다.

## 4. 전역 상태와 갱신 방식

| Context | 하는 일 |
|---|---|
| `AuthContext` | 로그인 상태·세션 만료 처리 |
| `RobotStatusContext` | **`/robot/status` 를 5초마다**(백그라운드 탭은 15초) 폴링해 모든 화면이 공유. 응답이 안 오면 `unreachable` 로 두고 로봇 상태 값을 믿지 않음. 응답 헤더 `X-Places-Rev`(장소 데이터 지문)가 바뀌면 장소 목록을 다시 받음 |
| `AlertContext` | 알림 목록·안 읽은 수 |
| `PageLoadingContext`, `SidebarContext` | 전역 로딩·사이드바 |

- 갱신은 **푸시가 아니라 폴링**입니다(영상은 WebRTC, 매핑·재조정 일부는 WebSocket). 폴링 훅은 `useVisibilityAwareInterval` — 숨은 탭에서는 주기를 늘립니다.
- `(pages)/layout.tsx` 는 로그인 여부를 확인하고(없으면 `/login`, 만료면 `/login?reason=session_expired`), 아래 **전역 알림 감시자**를 항상 올려 둡니다. 각 감시자는 백엔드 알림·상태를 보고 모달을 띄웁니다.

| 감시자(`components/common/*AlertWatcher.tsx`) | 띄우는 모달 |
|---|---|
| `InitPoseAlertWatcher` | 위치 확인·재조정 필요(`InitPoseConfirmModal`, `RelocalizeModal`) |
| `GuideFollowAlertWatcher` | 방문객 동행 이탈(`GuideFollowLostModal`) |
| `ThermalAlertWatcher` | 고온 감지 |
| `BatteryResumeAlertWatcher` | 배터리 부족 충전 후 이어 가기 확인(`BatteryResumeModal`) |
| `GuideBatteryAbortAlertWatcher` | 배터리 부족으로 안내 중단 |
| `StandbyMapHoldAlertWatcher` | 상시 대기 시작 보류(대기 장소가 다른 층) |
| `NavHoldAlertWatcher` | 주행 막힘 운영자 선택(재시도/건너뛰기/중단) |
| `GuideTtsFailedAlertWatcher` | 안내 중 발화 실패 |

## 5. API 호출 규칙

- 모든 호출은 `lib/api.ts` 의 `apiFetch` 를 거칩니다(쿠키 `credentials: include`). 401 이면 `tryRefresh()`(`/api/auth/refresh`, 재시도 2회·시도당 10초)로 갱신하고, 무효면 세션 만료로 확정해 추가 호출을 차단합니다. 탭 사이는 `BroadcastChannel("auth_refresh")` 로 갱신을 공유(5초 디바운스).
- 영역별 클라이언트: `lib/alertData·armApi·batteryResumeApi·cameraView·floorInfo·logData·navHold·robotInfo·statisticsApi·videoData.ts`, 음성은 `…/tabs/voice/voiceApi.ts`·`guideScenarioApi.ts`.
- **도메인 판정은 `lib/` 의 단일 소스**를 씁니다: `occurrenceStatus`(회차 상태), `scheduleMode`, `taskType`, `placeFilter`, `pathOrder`, `robotLiveness`(로봇 생존 판정), `yaw`, `navReach` 등(대부분 테스트 동반). 화면에서 같은 판정을 다시 만들지 마세요.

## 6. 개발·검증 명령

```bash
cd Frontend
npm ci
npm run dev          # 3000, 백엔드 8010 으로 프록시
npx tsc --noEmit     # 타입 검사
npm test             # vitest 1회 실행 (npm run test:watch 는 감시)
npx eslint <바꾼 파일>
npm run build        # 정적 export → out/
```

- 화면 변경은 실제 코드 기준 미리보기를 먼저 보이고(프로젝트 규칙), 배포는 08번 문서 3-1 절차입니다(프론트도 같은 절차).
- 새 화면을 만들 때는 기존 모달·셀렉트·`lib/` 판정을 재사용하세요.
