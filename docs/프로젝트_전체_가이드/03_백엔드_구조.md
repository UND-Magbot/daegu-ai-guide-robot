## 4. 인증·권한

- 로그인은 JWT 를 쿠키로 주고받습니다. 접근 토큰 만료 1557분, 갱신 토큰 7일(`auth/constants.py`). `JWT_SECRET_KEY` 가 없으면 기동 실패.
- **권한 등급:** `UserInfo.Permission` 1 = 최고 관리자(모든 메뉴), 2 = 관리자(`require_admin` 이 1·2 허용), 그 밖 = 일반 사용자 (`auth/dependencies.py:86,142-147`).
- **메뉴 권한:** `menu_info`(메뉴 트리)와 `user_permission`(사용자×메뉴)을 `require_permission("<메뉴키>")` 가 검사합니다. 기본 메뉴는 대시보드·작업관리·운영관리(로봇·사업장)·맵 관리(편집·장소·경로)·데이터관리(영상·통계·로그·음성)·알림·설정(메뉴 권한·비밀번호·DB 백업). 관리자·일반 사용자의 기본 부여 메뉴는 `seed.py` 의 `MANAGER_MENUS`·`USER_DEFAULT_MENUS`.
- **사업장 범위:** `is_admin`(= Permission 1, `auth/dependencies.py:142`)이 아니면 자기 `BusinessId` 의 데이터만 봅니다(예: 로그 조회 `logs/routes.py`). 로그 조회에서는 Permission 2(관리자)도 사업장 범위가 적용됩니다(다른 API 는 각 라우터에서 확인 필요).
- **Jetson 음성 에이전트**는 사람 로그인이 아니라 고정 토큰 `X-Agent-Token`(`.env` `AGENT_TOKEN`)을 씁니다. 미설정이면 503, 불일치면 401(`database/routes/agent_bridge.py:53-62`).
- 로그인 실패 횟수 잠금은 없습니다(401 과 감사 기록만, `auth/service.py:25-38`).
- 로봇 제어 API(이동·충전·모드 등)는 라우터 단위로 로그인 잠금이 걸려 있습니다(10-19 배포). `camera.py` 의 일부(`public_router`)만 공개 경로입니다.
- 작업(스케줄) 등록·수정은 `_require_robot_scope` 가 사업장 범위를 검사합니다. 최고 관리자가 아니면 다른 사업장 로봇의 작업을 등록·수정할 수 없습니다(403, `database/routes/schedule.py:634-639,652,1126`).
- `/alerts/external/thermal-event` 는 인증이 없습니다(사내망 신뢰).

## 6. 전역 상태·락·순환 참조 주의

- **작업자 1개 전제.** 동시 실행 방지는 DB 가 아니라 **프로세스 안 잠금**에 의존합니다. uvicorn 작업자를 늘리면 깨집니다.
- 같은 트랜잭션 안 재조회는 처음 값이 나옵니다(MariaDB 격리 수준).
- **순환 참조:** `cluster.deps` ↔ `robot_control.charge`. 새 import 를 넣을 때 주의하고, 함수 안에서 늦게 import 하는 패턴이 곳곳에 있습니다.
- `user_cache` 의 "현재 로봇"은 `ROBOT_IP` 와 같은 로봇을 잡습니다(`main.py:179-190` — 시뮬레이터처럼 나중 등록된 로봇이 잡히는 갈림 방지).
- `runtime._lock` 안에서 외부 호출을 하면 정체가 생길 수 있습니다(로그 알림 게이트가 `rt_mod._lock` 을 잡고 `_derive_network` 호출 — `logs/service.py:245-250`).
- 줄바꿈(CRLF/LF)은 파일별로 원본에 맞춥니다. `git apply` 로 반영하면 파일 전체가 CRLF 로 바뀌므로(`autocrlf=true`) 쓰지 않습니다.
