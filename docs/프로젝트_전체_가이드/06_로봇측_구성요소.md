## 1. 중계기 `robot_receiver/` — NOS 보드에서 실행

**역할:** 관제 ↔ 로봇 본체 사이의 번역기. 관제의 UDP 40000·TCP 40001 JSON 명령을 본체의 제조사 ASDU(UDP 30000·TCP 30001)로 바꿔 보내고, 본체 응답과 ROS2 보조 정보를 합쳐 관제에 돌려줍니다. NOS 안에서 root 로 도는 ROS2 보조 노드 몇 개와 함께 동작합니다.

### 1-2. 중계기가 지키는 규칙
- 이동 명령 ack 는 "4.5초 안에 본체로 보냈는지"까지만 의미합니다(본체 수락 여부 아님). 늦으면 `ack:false` 를 먼저 돌려주고 명령은 나중에 보내며, 다지점은 `n` 이 있으면 수락으로 봅니다.
- NAV 보내기 전에 **모드 리셋(Mode 0)** 을 하고 보행 전환(0x1001) 확인을 12초 기다립니다. 확인 못 해도 NAV 는 그냥 보냅니다(로그만).
- 새 명령(NAV·STOP·CANCEL_NAV·SIT·수동 이동)이 오면 앞서 대기 중이던 NAV 는 버립니다.
- 다지점 묶음 크기 초과(바이트 > 976 또는 64점 초과)는 `{"ack":false,"error":…}` 로 거절. 본체가 약 1KB 넘는 명령을 해석하지 못함(10-27 실측).
- 본체가 1초 무응답이면 마지막 캐시를 유지하고 경과를 `age`/`receiver_age` 로 알립니다.
- 중계기 환경 변수 `NAV_CONTINUE_SKIP_RESET` 은 관제 `NAV_KEEP_GAIT_ON_ARRIVAL`·`NAV_CONTINUOUS_PASS` 와 **짝**입니다(관제만 켜면 오히려 나빠짐).

## 2. 음성 `robot_voice/` — Jetson 에서 실행

**역할:** 마이크 → 말 인식(STT) → 목적지·응답 판정 → 관제에 이동 요청 → 시나리오 단계 진행 → 말하기(TTS). **판정은 Jetson 이 하고** 관제는 시나리오(번들)를 주고 결과를 받습니다.

### 2-1. 파일
| 파일 | 하는 일 |
|---|---|
| `main.py` | 메인 루프. 세션이 열리면 `ScenarioRunner` 를 돌리고, 대기 중에는 호출어("큐리야")만 듣음. 상시 대기 근무의 응대 방식이 '단순 동작'(관제 `responseMode=motion`)이면 대기 장소에서 "큐리야, 앉아/일어서"만 듣고 관제에는 올리지 않음. 호출어는 **응답 대기 중에만 면제** |
| `scenario.py` | 시나리오 단계 엔진(WaitFor: `none`/`user`/`operator`/`arrival`). `operator` 단계만 네트워크가 필수 |
| `backend.py` | 관제 클라이언트. 번들 받기(로컬 캐시)·세션 보고. 인증 `X-Agent-Token`. 관제가 끊겨도 마지막 캐시로 계속 동작 |
| `ai.py` | OpenAI STT/TTS·목적지 판정(LLM)·힌트 에코 환각 필터. TTS 실패 시 로컬 TTS(:8090) 대체·600초 동안 OpenAI 회피 |
| `audio.py` | 마이크 녹음(에너지 기반 VAD)·스피커 재생. 장치는 이름 힌트로 탐색(ReSpeaker XVF3800 마이크, UACDemo 스피커). 출력 스트림은 열어 둠 |
| `stt_server.py` | **로컬 STT HTTP 서버**(faster-whisper small, CUDA, :8091). 2026-09-30 OpenAI 크레딧 소진 대비로 만듦. 품질 필터(no_speech>0.6, logprob<−1.0)로 버림 |
| `follow.py` | 이동 중 동행 확인("잘 따라오고 계신가요?") |
| `wakeword.py` | STT 텍스트에서 호출어 판정 |
| `motion_cmd.py` | 전시용 "큐리야, 앉아/일어서"(단순 동작 응대). **관제를 거치지 않고** receiver UDP 40000 에 직접 SIT/STAND 전송. 주행·충전·상태 모름이면 보내지 않음. 켜고 끄는 스위치 파일은 없고, 단순 동작으로 등록한 상시 대기 근무가 도는 동안에만 듣는다 |
| `auto_answer.py` | **시험용 자동 대답**. `/var/lib/robot-voice/auto_answer.json` 이 있으면 마이크 대신 정해 둔 대답을 씀(안내 반복 '무한'과 함께). 파일을 지우면 끔 — **켜 둔 채 잊으면 무한 반복**(11-05 사례) |
| `diag.py`·`beam_probe.py` | 듣기 진단 기록(turns.jsonl·wav), 리허설용 말소리 방향·크기 기록기 |
| `session.py` | 방문자 세션 상태(10-15 기록상 import 하는 곳 못 찾음) |
| `config.py` | 모든 설정은 환경 변수(`/etc/robot-voice.env`, systemd `Environment=`) |
| `install.sh` | Jetson 설치(venv·`/opt/robot/voice` 복사·유닛 등록). **시연 직전 실행 금지** |
| `respeaker_tune.sh`·`systemd/` | USB 재인식 때 XVF3800 파라미터 재주입·robot-voice 재시작, `robot-voice.service`·`stt-server.service`·`respeaker-tune.service`·udev 규칙 |

### 2-2. 동작 요점
- **필수 설정 4개**가 없으면 기동 실패 후 systemd 가 5초 뒤 재시작: `OPENAI_API_KEY`, `AGENT_TOKEN`, `ROBOT_ID`, `BACKEND_BASE`.
- 세션 폴링은 3초마다 `GET /voice/session/current`. 이동 요청은 멘트 끝 1초 전에 `/move`, 이후 `/robot/nav` 를 1초마다 폴링하며 장애물 멘트·질문·방향 안내 처리.
- 음성 인식: `STT_LOCAL_URL` 이 있으면 Jetson 안 8091, 없으면 OpenAI(`whisper-1`). 로컬→OpenAI 자동 대체는 없음. 실제 운영값(11-06): `http://127.0.0.1:8091/stt`.
- 시나리오·목적지 사전은 관제 화면에서 고치면 번들로 Jetson 에 반영됩니다. 반면 관제 화면의 "음성 튜닝값"(`voice_config`: 인식 임계, 무음 시간, 말 속도, 인식 모델 등)은 번들에 실리지만 Jetson 코드가 사용하지 않아 반영되지 않습니다(`robot_voice/backend.py` 의 `voice_config()` 호출처 없음). 이 항목들은 Jetson 의 `/etc/robot-voice.env` 로 설정합니다.
- **실행본은 `/opt/robot/voice/robot_voice`** 입니다. 작업 폴더만 고치면 안 먹습니다(10-12 사례).
- OpenAI 키는 관제 `.env` 와 같은 키를 씁니다(크레딧 소진 이력 있음 — 현재 잔액 확인 필요).
- 시계 맞춤은 robot_voice 코드에 없습니다.

## 4. 영상 중계 `MediaMTX/`

- 로봇 RTSP(H.265, 8554 video1·video2)를 ffmpeg 로 H.264 재인코딩해 WebRTC(WHEP, 8889)로 송출. compose 는 공식 이미지 `bluenviron/mediamtx:latest-ffmpeg` 에 **`mediamtx.local.yml`** 을 마운트합니다.
- `mediamtx.yml`(옛 무재인코딩 설정)·`Dockerfile`·`mediamtx` 바이너리는 현행 compose 가 쓰지 않습니다(정리 후보). `mediamtx.yml` 의 열화상(`thermal`) 경로에서는 카메라 계정을 뺐습니다. 이 옛 설정을 다시 쓸 때만 로컬에서 `rtsp://계정:비밀번호@…` 형태로 고치고 그 변경은 커밋하지 않습니다(계정 값은 `robot_vision/thermal.env`).
- 망이 바뀌면 `mediamtx.local.yml` 의 영상 원본 주소와 `webrtcAdditionalHosts`(관제 PC 주소)를 고치고 컨테이너를 **재생성**합니다. `ROBOT_IP` 를 바꿔도 MediaMTX 소스 IP 는 자동으로 바뀌지 않습니다.
- 19997(상태 API)은 로컬 전용(127.0.0.1), API 인증이 걸려 있습니다(`MEDIAMTX_API`).
- 화면은 `framesDecoded` 가 3초 동안 변하지 않으면 LIVE 대신 "마지막 화면 N초 전"을 표시합니다(10-23). 오래 두면 검은 화면인데 LIVE 로 보이는 문제는 원인 미확정(`11_이슈대장.md` CAM-03).

## 5. 로그 수집 `tools/robotlog/`

- 컨테이너 `control-robotlog` 가 NOS·본체·Jetson 로그를 주기적으로 받아 `./backend_logs/robot/<날짜>/` 에 보관(기본 90일, `ROBOTLOG_RETENTION_DAYS`).
- 빠른 주기(`ROBOTLOG_FAST_SEC`): NOS 우리 서비스 journal(약 8분이면 지워짐)·장애물 감지 좌표·Jetson. 느린 주기(`ROBOTLOG_SLOW_SEC`): 제조사 로그.
- 파일: `collector.py`(수집), `agent.py`, `remote.py`(SSH), `robotlog.py`(조회 명령). Jetson 수집은 `ROBOTLOG_JETSON_*`(키 경로) 설정 시에만. 2단계(수집)는 11-05 기동, 하루치 확인은 남음.

## 6. 단순 동작 응대 (전시용 앉아·일어서)

- **쓰는 법:** 작업 등록 › 상시 대기 › 호출 방식 `마이크` › 응대 방식 `단순 동작 (앉아·일어서)` 로 등록합니다(마이크가 없는 로봇은 고를 수 없음). 근무 시간에 대기 장소에 도착하면 로봇이 안내 멘트("'큐리야, 앉아' 또는 '큐리야, 일어서'라고 말씀해 보세요")를 하고 그 두 명령만 듣습니다. 근무가 끝나면 저절로 멈춥니다.
- **동작:** Jetson 이 receiver 에 SIT/STAND 를 직접 보냅니다(관제를 거치지 않음). 주행 중·충전 중·상태 불명·이미 그 자세·동작 중이면 멘트로 알리고 보내지 않습니다. 목적지 안내는 하지 않으며, 목적지 호출이 올라와도 관제는 409 로 거절합니다. 응대 세션 기록·건수 통계에는 남지 않습니다.
- **관제 쪽:** `schedule_info.StandbyResponseMode='motion'` → `GET /DB/agent/standby-context` 의 `responseMode="motion"` → Jetson `main._standby_motion_once`. 근무 칩에는 "단순 동작" 꼬리표가 붙고 [관제 개입] 버튼은 없습니다.
- **자동 앉기:** 상시 대기 근무에는 자동으로 앉히는 코드가 없습니다(`StandbyIdleSitSec` 는 읽는 곳이 없음). 모터 과열(95/100°C)이나 배터리 부족 때의 충전소 복귀·앉기 보호는 이 근무에서도 그대로 동작합니다.
- **예전 방식 정리:** 원격 PC 의 `motion_on.bat` 스위치 방식과 Jetson 설정 `MOTION_CMD_ENABLED`·`MOTION_ONLY`·`MOTION_FLAG_*` 는 없어졌습니다. Jetson `/etc/robot-voice.env` 에 이 값이 남아 있으면 무시되지만 지워 둡니다(`12_남은일_결정대기_위험.md` 2절).
