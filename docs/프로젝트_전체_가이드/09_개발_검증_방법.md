# 09. 개발·검증 방법

- 작성일 2026-11-26 · 근거: `sim/README.md`, `Frontend/package.json`·`vitest.config.ts`, `git` 상태(2026-11-26 조회).

## 1. 개발 원칙 (이 프로젝트 고유 규칙)

1. **기능 구현·수정은 코드를 고치기 전에 사전 시뮬레이션(presim)** 을 합니다: 변경안을 사본에 적용해 시뮬을 실제로 돌리고 → 현행 vs 변경 결과를 보고하고 → **승인받은 뒤** 작업 폴더에 반영합니다. 문서·문구만 바꾸는 작업은 "시뮬 생략(사유)"을 알리고 진행합니다.
2. **작업 폴더 ≠ 실행본.** 고친 뒤 배포해야 반영됩니다(`08_설정_환경변수_배포.md`). 상태(배포 여부·설정값·판정 시간)는 메모가 아니라 실행 중 환경(환경 변수·컨테이너 코드·설치본)에서 확인합니다.
3. **시험은 관제를 거쳐서만** 합니다. 제조사 앱·직접 스크립트 주행은 결과가 무효이거나 오경보를 냅니다.
4. **근거 없는 추측 금지.** 단정하는 문장마다 근거(`파일:줄`, DB·로그 조회, 매뉴얼)를 댈 수 있어야 하고, 못 대면 먼저 확인하거나 "추정:"을 붙입니다. 변수·함수 이름이나 주석 한 줄만 보고 동작을 말하지 않습니다(예: `no_route=True` 는 "관제가 노드 경로를 계산하지 않음"이지 "직선 주행"이 아닙니다). 로봇 본체·NOS 의 실제 동작은 관제 코드만으로 알 수 없으니 본체 로그·실기 기록·매뉴얼 근거가 없으면 추정으로 적습니다.
5. 보고는 **"실기 미확인 / 미배포 / 미커밋 / 추정"을 나눠** 적고, 틀린 앞 설명은 지우지 말고 "정정"으로 남깁니다.
6. 결정할 것은 번호 붙은 표(질문·권장안)로 묶고, 화면 변경은 실제 코드 기준 미리보기를 먼저 보입니다.
7. 새 환경 변수는 코드 + `.env.example` + compose 3개를 함께 고칩니다(08번 문서 2절의 4곳 수정과 대조 방법).
8. 파일별 줄바꿈 방식(CRLF/LF)은 원본에 맞춥니다.

## 2. 사전 시뮬레이션 하네스 (`sim/`)

관제 백엔드 코드를 **가상 시계 + 가짜 로봇** 위에서 실제로 돌려, 수정 전·후를 같은 시나리오로 비교합니다. 운영 DB·로봇·중계기에는 닿지 않습니다(임시 SQLite, 실제 소켓 송신 차단, `.env` 미사용).

```bat
sim\run.bat sim\scenarios\nav_basic.py                          :: 작업 폴더 Backend 만
sim\run.bat snapshot sim\out\cand_작업명                         :: 변경안 사본(Backend/app) 만들기
sim\run.bat sim\scenarios\내시나리오.py --cand sim\out\cand_작업명   :: 현행 vs 변경 비교
sim\run.bat sim\scenarios\내시나리오.py --base git:HEAD --cand ...  :: 현행을 커밋 기준으로
```

- 첫 실행 때 `sim\.venv` 를 만듭니다. 결과 표는 화면, 전체 결과(명령열·로그 꼬리)는 `sim\out\*.json`. 마지막 변형에서 기대 판정이 하나라도 실패하면 종료 코드 1.
- 구성: `sim/run.py`·`run.bat`, `sim/harness/`(`backend.py`·`clock.py`·`robot.py`·`worker.py`), `sim/scenarios/`(**91개** — 회귀 묶음, 예: `nav_basic`, `multipoint`, `node_route`, `nav_hold`, `door_gate`, `battery_policy`, `guide_prerun`, `auto_reloc_1106`, `biz_guard`, `editor_s1`), `sim/out/`(사본·결과, 지워도 됨).
- 시나리오 작성:

```python
from harness import scenario

@scenario("도착 후 Regular 복귀", expect=lambda r: r["mode"] == "Regular" and r["errors"] == 0)
def arrive(sim):
    sim.move([(3, 0, True), (6, 3)])          # (x, y[, 통과점])
```

| 도구 | 용도 |
|---|---|
| `sim.move(points, keep_gait=, charge=, stop_at=)` | 웨이포인트 이동을 `nav_thread` 로 끝까지 |
| `sim.run(fn, until=pred)` | 아무 Backend 함수나 가상 시계 위에서 |
| `sim.at(초, fn)` / `sim.wait(초)` | 끼워 넣을 사건 / 시간 흘리기 |
| `sim.robot.drop_comm(초)` / `hold(초)` / `place(x, y)` | 통신 두절, 제자리 대기, 위치 지정 |
| `sim.sm`, `sim.pl`, `sim.rt`, `sim.sender` … | Backend 모듈(속성을 바꿔 상황 설정) |
| `@scenario(..., params={"speed": 0.3}, env={...})` | 로봇 규칙 수치, import 전 환경 변수 |

  결과 dict 키: `pos gait mode posture charging executing switches rejects races charge_mode0 dropped arrivals cmds sim_sec errors events`.
- **재현하는 것/못 하는 것:** 가짜 로봇 규칙(`harness/robot.py` 머리말)은 실기에서 확인한 것만 담습니다. 벤더 펌웨어 재정렬, 측위 품질, Wi-Fi 타이밍, 여러 스레드의 실제 동시 실행은 재현하지 않습니다 → 보고서에 "실기 확인 필요"로 적습니다. 새로 실측한 로봇 동작이 생기면 `robot.py` 규칙과 `RobotParams` 에 반영합니다.

### 2-1. presim 절차 (요약)

| 등급 | 대상 | 할 일 |
|---|---|---|
| 생략 | 문서·주석·문구·로그 메시지, 동작 무관 설정 | "시뮬 생략(사유)" 알리고 진행 |
| 경량 | 함수 하나의 판정·계산 로직 | 입력·출력 케이스 3~6개 |
| 전체 | 상태 머신, 타이밍, 로봇 명령 순서, 여러 모듈, 동시성 | 하네스 시나리오로 정상·경계·장애 흐름까지 |

1. 변경안 사본 `sim\run.bat snapshot sim\out\cand_<작업명>` → 사본(`sim\out\cand_<작업명>\app\...`)에서 수정(작업 폴더는 건드리지 않음, 사본은 반드시 `sim\out` 아래 — Windows 경로 길이 한도).
2. 시나리오 `sim\scenarios\<작업명>.py`: **현행에서 문제가 재현되는 것**(버그 수정이면 필수) + 고친 뒤 기대 동작 + 회귀 확인용 기존 흐름 + 경계·장애. `expect` 는 바뀌어야 할 것과 **바뀌면 안 되는 것**을 모두 적습니다.
3. 중계기·음성·프론트처럼 하네스가 덮지 않는 코드는 `sim\out\<작업명>\` 에 단독 스크립트(프론트는 vitest)로 같은 방식(현행 vs 변경 표)으로 검증합니다.
4. 실행 `sim\run.bat sim\scenarios\<작업명>.py --cand sim\out\cand_<작업명>`. 현행에서 재현 시나리오가 실패하지 않으면 시나리오가 문제를 못 잡은 것입니다.
5. **보고 형식:** ① 바꾸려는 것 ② 결과 표(현행|변경|차이)와 통과 수 ③ 명령열 차이 ④ 새 위험·부작용(숨기지 않음) ⑤ 시뮬로 확인 못 한 것(실기 타이밍·벤더 펌웨어·측위 품질·동시성, 추론은 "추론" 표시) ⑥ 진행 여부 질문 — **승인 전에는 작업 폴더를 수정하지 않습니다.**
6. 승인 후: 사본에서 검증한 내용을 **같은 내용으로** 작업 폴더에 반영(다르게 고치면 다시 돌림) → `--cand` 없이 한 번 더 실행해 통과 확인 → 시나리오는 회귀 묶음으로 남김.
- **반영은 줄 단위로(Edit)** 합니다. 사본을 통째로 복사하면 그 사이 다른 세션이 고친 줄이 지워집니다(10-29 사례: config.py 3줄 소실). `git apply` 도 쓰지 않습니다(`autocrlf=true` 라 파일 전체가 CRLF 로 바뀜). 반영 전 `diff` 확인.

| 대상 | 방법 |
|---|---|
| 백엔드 | **별도 pytest 묶음 없음**(`Backend/tests` 없음, 10-15 에 삭제). 검증은 `sim/` 하네스 |

- 현재 환경에서 못 한 검증은 **무엇을 왜 못 했는지** 보고에 정확히 적습니다.

## 4. Git·커밋 규칙

- **커밋은 요청이 있을 때만**, **경로를 지정해 세션(작업)별로 나눠** 하고, **원격 저장소에 올리지 않습니다**(푸시는 사용자가 결정).
- 비밀값 파일 주의: `.env`·`.env.bak_*`, `Backend/data/_*.py`(장비 SSH 계정 평문), `robot_vision/thermal.env`(열화상 카메라 계정). 저장소가 공개이므로 계정·비밀번호를 코드·설정 파일에 직접 쓰지 않습니다. `.gitignore` 에서 `.env.*`(단 `.env.example` 제외), `backend_logs/`, `Backend/recordings/`, `node_modules/`, `Frontend/out/`, `noah/` 를 제외합니다. **`.bak_날짜` 형식 백업 파일은 일부 규칙에 걸리지 않으니** 커밋 전 `git status` 로 확인.
- 커밋 메시지는 Conventional Commits 형식(`feat(scope): …`)을 씁니다(최근 이력 예: `fix(nav): …`, `chore(nos): …`).

## 5. 작업 문서 관행

- 작업 하나를 마칠 때마다 이슈 대장(`11_이슈대장.md`)·남은 일(`12_남은일_결정대기_위험.md`)을 함께 갱신합니다(`00_README_읽는순서.md` 의 갱신 규칙).
- 보고·응답은 **국문**으로, 영문 용어는 꼭 필요한 명령·파일명만 씁니다.

## 6. 개발 환경 메모

- 백엔드 로컬 실행은 도커가 기본입니다(`start.bat`). 파이썬 3.10.9(`.python-version`), 의존성 `Backend/requirements.txt`.
- 프론트: Node 20(도커 이미지 기준), `Frontend` 에서 `npm ci` 후 `npm run dev`(3000, 8010 프록시).
- Windows + Git Bash: 컨테이너 경로는 `MSYS_NO_PATHCONV=1`, 한글 출력은 `PYTHONIOENCODING=utf-8`. 한글 bat 는 첫 줄에서 UTF-8 로 다시 실행.
- 컨테이너는 켜져 있는데 포트 접속이 안 되면 `netsh int ipv4 show dynamicport tcp`(시작이 49152 여야 함).
