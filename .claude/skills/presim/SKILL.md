# 사전 시뮬레이션(presim)

코드를 바꾸기 **전에** 변경안을 사본에 적용해 실제로 실행하고, 현행과 같은 시나리오로 비교한 결과를 보고한다.
승인을 받은 뒤에만 작업 폴더에 반영한다.

## 0. 등급 정하기

| 등급 | 대상 | 할 일 |
|---|---|---|
| 생략 | 문서·주석·문구·로그 메시지, 동작 무관 설정 | "시뮬 생략(사유)" 한 줄 알리고 바로 진행 |
| 경량 | 함수 하나의 판정·계산 로직 | 입력·출력 케이스 3~6개 실행 |
| 전체 | 상태 머신, 타이밍, 로봇 명령 순서, 여러 모듈, 동시성 | 하네스 시나리오로 정상·경계·장애 흐름까지 |

애매하면 한 단계 위로 잡는다.

## 1. 변경안 사본 만들기 (작업 폴더는 건드리지 않는다)

```bat
sim\run.bat snapshot sim\out\cand_<작업명>
```

변경안은 `sim\out\cand_<작업명>\app\...` 에서 고친다. 사본은 반드시 `sim\out` 아래(Windows 경로 길이 한도).

## 2. 시나리오 작성

- 관제 Backend: `sim\scenarios\<작업명>.py` 에 `@scenario` 로 작성한다. 시작점은 `sim\scenarios\nav_basic.py`, API 는 `sim\README.md`.
- 시나리오는 **현행에서 문제가 재현되는 것**(버그 수정이면 필수) + **고친 뒤 기대 동작** + **회귀 확인용 기존 흐름** + **경계·장애**(통신 두절, 도착 직후 연속 이동, 정지, 충전 중 등)를 포함한다.
- `expect` 는 바뀌어야 할 것과 바뀌면 안 되는 것을 모두 적는다. 판정 없는 시나리오는 "관찰용"으로만 쓴다.
- receiver·voice·Frontend 처럼 하네스가 덮지 않는 코드는 `sim\out\<작업명>\` 에 단독 스크립트(또는 Frontend 는 vitest)로 실제 함수를 불러 같은 방식(현행 vs 변경 표)으로 만든다.
- 가짜 로봇에 없는 동작이 필요하면 추측으로 넣지 말고, 넣은 가정을 보고서에 적는다. 실측 근거가 있는 규칙만 `sim\harness\robot.py` 에 반영한다.

## 3. 실행

```bat
sim\run.bat sim\scenarios\<작업명>.py --cand sim\out\cand_<작업명>
```

- 기본 현행 = 작업 폴더 `Backend`. 미커밋 변경과 섞이면 안 될 때는 `--base git:HEAD`.
- 현행에서 재현 시나리오가 실패하지 않으면 시나리오가 문제를 못 잡은 것이다. 시나리오를 고친다.
- 💥 예외가 나면 하네스 연결 문제인지 코드 문제인지 구분해 적는다.

## 4. 보고 (이 형식 그대로)

1. **바꾸려는 것** — 한두 줄
2. **결과 표** — run.py 가 출력한 표(현행 | 변경 | 차이)와 통과 수
3. **명령열 차이** — 달라진 시나리오만
4. **새 위험·부작용** — 변경안에서 나빠진 지표가 있으면 숨기지 않는다
5. **시뮬로 확인 못 한 것** — 실기 타이밍, 벤더 펌웨어 반응, 측위 품질, 실제 스레드 동시성 등. 추론으로 판단한 부분은 "추론"으로 표시
6. **진행 여부 질문** — 승인 전에는 작업 폴더를 수정하지 않는다

## 5. 승인 후

- 사본에서 검증한 변경을 작업 폴더에 같은 내용으로 반영한다(다르게 고치면 다시 돌린다).
- 반영 후 같은 시나리오를 `--cand` 없이 한 번 더 실행해 작업 폴더 기준 통과를 확인한다.
- 시나리오 파일은 `sim\scenarios` 에 남겨 회귀 묶음으로 쓴다. 사본 폴더(`sim\out\cand_*`)는 지워도 된다.
